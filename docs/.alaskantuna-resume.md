### #239, the delisted model — abandoned mid-change, on purpose

The gateway no longer serves `moonshotai/Kimi-K2.6`; it returns HTTP 400, and GonkaRouter have confirmed it is prone to
downtime. `src/server/gateway/models.ts` still lists it.

I started removing it and **stopped**, because it is a bigger change than it looks. There is uncommitted work in a
worktree at `/home/user/cekgu-video/wt/models` — `models.ts` reduced to two families, and `health.test.ts` rewritten for
two. That part is done and its 11 tests pass.

**What stopped it:** `src/server/extract/structure.test.ts` has a test named _"starts two models at once and leaves the
third until that wave settles"_. The extract wave assumes three families, so dropping one changes the wave arithmetic
and the test's premise together. That is a two-part change — make the wave count families rather than assume three, then
re-express the test against that — and it is the wrong shape to attempt minutes before a submission.

**It is not urgent.** Kimi sorts last in `healthyOrder()`, so it is only reached as a fallback, and a fallback that
fails leaves the item Unverified exactly as it would have been. Two families still cross-verify, so the track
requirement holds.

**Two things about it worth knowing before someone finishes it:**

- Removing the third family makes the exclusion branch in `healthyOrder()` dead. With two configured families, a failing
  one is never dropped, because dropping it leaves one candidate and one candidate cannot produce two distinct readings.
  The rewritten test in that worktree asserts exactly this, and it is the better assertion.
- **Deck slide 08 names Kimi-K2.6 as Reader B**, and the recorded film shows that slide. The deck already disagrees with
  the live gateway regardless of what the code says, because the delisting is the gateway's doing. Changing the deck now
  would desync it from a film that is finished. That is a call for whoever owns the deck, not a fix to slip in.

## Working notes

**The guard hook has two false positives** worth knowing before losing time to them. It matches command substrings, so
it blocks a `git push` compounded with anything containing "main", and it read `git commit -F` beside a push as a force
push. Split the commands. It also blocked `pkill -f "<pattern>"` matching my own shell — kill by PID from
`ps -eo pid,args | grep "[p]attern"` instead.

**`bun test` fails two tests locally for anyone with a real `.env`.** `GEMINI_API_KEY` being set makes
`src/server/routes/extract.test.ts` take the live path and reach a Postgres that is not running.
`GEMINI_API_KEY= bun test` is clean, and CI has no `.env`.
