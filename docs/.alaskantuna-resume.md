### The one thing Codex found that is worth keeping

It read the chat speech work carefully and **found a real race that AlaskanTuna's own testing missed**. Verified against
the code before writing it here, not taken on trust:

`speak()` returns a handle whose `cancel()` calls `engine.cancel()` (`src/client/mascot/voice.ts:120`), and
`speechSynthesis.cancel()` is **global** — it stops every utterance in the browser, not just the one that handle
started.

`Mascot.tsx` speaks the record summary and then arms `setTimeout(dismiss, CAPTION_HOLD_MS * n)`
(`src/client/mascot/Mascot.tsx:121`), and `dismiss()` calls that global cancel.

So: a record finishes, the summary speaks and arms its dismiss timer; the reader opens the chat and gets an answer
inside that window; the chat starts speaking; **the summary's old timer fires and cuts the chat answer off
mid-sentence.** Nothing in the chat modal is wrong — it is the summary's timer reaching across and stopping speech it
does not own.

**This is a defect in #235 as it stands.** Two ways out, either acceptable:

1. Make cancellation apply only to the current speech owner, so a stale handle cannot stop a newer one.
2. Release the summary's speech and clear its timer when the chat opens. `Mascot.tsx` already knows `chatOpen` — it
   stands its stage down on exactly that signal — so the timer can be cleared beside it.

Option 2 is the smaller change and uses a signal that already exists. **Neither has been done.**

## Fanning work out: the OpenCode and Devin CLIs

Both are installed: `opencode` 1.18.29 at `~/.bun/bin/opencode`, `devin` 3000.6.7 at `~/.local/bin/devin`. Full guidance
is in `~/.claude/skills/opencode-fanout/SKILL.md` and `~/.claude/skills/devin-fanout/SKILL.md`; this is the short
version plus what this session observed.

**Six concurrent workers is the ceiling for either.** Past that they contend for the same files and reviewing them costs
more than they saved.

### What to send, and what to keep

Send mechanical work: the same transformation across many files, per-file inventories, boilerplate with a worked
example, drafting from a spec you already wrote. Keep judgement: architecture, naming, API shape, security, deciding
what the structure should be. **If the brief takes longer to write than the task takes to do, do the task** — which is
exactly what went wrong below.

### OpenCode

```bash
opencode models | grep -iE "glm|claude"        # never assume an id; the catalogue drifts
opencode run --model openrouter/z-ai/glm-5.3-flash \
  --dir <absolute path> "<the whole brief as one argument>" \
  > <log path> 2>&1
```

- `--dir` is a hard boundary. Reads outside it are auto-rejected **and the run still exits 0**. Copy inputs inside
  first.
- Redirect to a log file. OpenCode buffers the whole session and writes it at exit, so a 0-byte log means "not
  finished", never "not working" — never diagnose a stall from log size.
- Diagnose with CPU time instead: `ps -eo pid,etime,time,cmd | grep "[o]pencode run"`.
- **Never `pkill` on the full command line** — that pattern matches your own shell command and takes the wrapper with
  it. Use `pkill -x opencode`, or kill the PID from the `ps` above.

**Observed here, 5 Sept:** a worker on `openrouter/z-ai/glm-5.3-flash` was given a one-word edit to a single line of
`pitch-deck.html`. It ran 13 minutes 39 seconds on 6 seconds of CPU with an empty log and never touched the file — the
skill's own documented stall signature. Killed by PID; the edit took about ten seconds by hand. **Set a wall-clock
budget before dispatching, and when it passes do the work yourself rather than re-dispatching.**

### Devin

`swe-1-7` (SWE-1.7 Max) is free-tier at 262K context, which makes Devin the first worker to reach for on volume.

```bash
devin models list                              # read the prices; some are free
devin --model swe-1-7 \
      --permission-mode accept-edits \
      --respect-workspace-trust false \
      --prompt-file <path to the brief> -p \
      > <log path> 2>&1
```

- **A one-time interactive trust approval is required per directory before any headless run**, and no flag replaces it.
  If it has not been done here, ask a human to run `devin` in this directory, accept the prompt, and exit. They can type
  `! devin` at the Claude Code prompt to do it in-session.
- **A git worktree is a different directory** and has never been approved. Run in the approved checkout, or get the
  worktree path approved first. This project uses worktrees heavily, so expect to hit this.
- Put the brief in a file and pass `--prompt-file`. Inline prompts turn into shell-quoting archaeology, and heredocs
  interact badly with backgrounding.
- `--permission-mode accept-edits` is the default for fan-out. The trap: a worker needing to read a file _outside_ the
  workspace hits a confirmation it cannot show, logs `rejected a tool call that requires confirmation`, skips that part
  of the job, and **exits 0**.

### Verifying either one, which is not optional

**Both CLIs exit 0 when they have done nothing.** Never report success from an exit code.

```bash
ls -la <expected outputs>                       # exist, and non-trivial
git status --porcelain                          # what changed, including strays
grep -rn "/home/\|C:\\\\Users\|/tmp/" <output>  # no machine paths leaked into a committed file
tail -20 <log>                                  # what it said it did
grep -n "rejected a tool call" <log>            # Devin: gave up halfway and told nobody
```

Then read the parts that carry risk. A worker will fabricate a plausible column or quietly drop the row you cared about,
so for anything factual, diff it against the source of truth rather than against your expectations. Say in your report
what you corrected — that is the part that tells the next person whether to use a stronger model or a tighter brief.
